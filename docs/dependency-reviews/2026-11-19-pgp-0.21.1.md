# Dependency Review: pgp 0.21.1 public verifier

## Summary

- Date: 19 November 2026.
- Scope: `pgp` 0.21.0 to 0.21.1 for the existing bounded public-only Rust
  distribution verifier. Independent Astra security and Sol design reviews
  support the scoped clearance below after source and native qualification.
- Source review preceded the isolated candidate's manifest changes and
  execution on 19 November. The results below describe that candidate.
  The subsequent v0.44.1 integration follows the
  [complete crypto dependency decision](2026-11-19-crypto-update-decision.md).

## Classification

Elevated-risk: parsing and verifying untrusted cryptographic material, despite
the patch version and unchanged dependency graph. Approval is limited to the
existing v4 public RSA certificate and binary detached-signature route.

## Targets

- `pgp =0.21.1`, crates.io archive SHA256
  `c7275cbf21850789239e1be05d9a887e6bba6aa8085a81be09ca021c8379baef`.
- Published source commit `56a40045e1d7516e5ec02244ea2884c92bece45f`.
- Consumer and maintained `rpgpie` exact declarations must move together.
  No new library feature, execution surface or accepted algorithm is requested.

No execution-surface or release-age allowance is added. The two existing exact

## Release Age

The registry reports publication at `2026-11-11T15:48:34Z`, non-yanked,

## Advisory Review

Current RustSec records still affect `rsa 0.9.10` (RUSTSEC-2023-0071) and
`crypto-bigint 0.5.5` (RUSTSEC-2026-0387). The actual candidate resolver retains
both. The existing public-only non-exposure reasoning remains bounded; this
update neither fixes these crates nor removes or extends their exceptions.
The upstream package's newly added advisory ignore is not imported.

Trusted installed Barbican audited the actual candidate before compilation:
success, with only those two accepted findings. Candidate licenses, bans and
sources pass. The canonical candidate gate also passes audit and exact pin
reconciliation. This is not a claim of a clean advisory graph.

## Source / Upstream Review

Both exact archives are authenticated against registry checksums. Complete
package inventory has 715 files in each, with no added or deleted file. Forty-six
Rust files change. Production dependency and feature definitions are unchanged;
the packaged development lockfile is not the product lockfile. No new build
script, proc macro, native toolkit, process or network dependency is introduced.

The reviewed delta replaces indexing/slicing in armour, base64, bounded body
readers, public-key parameter decoding, MPI/serialization and hash prefixes with
checked access or equivalent iteration. Fixed-size digest-prefix comparisons
still fail closed if the computed hash is too short. V4 timestamp/fingerprint
encoding, signature trailers and short RSA MPI left-padding retain their byte
meaning. Public EC parameter decoding precedes Barbican's RSA-only certificate
check and was included in review. Secret/message packet tags are rejected before
their bodies are decoded; unsupported message/decryption APIs are not approved
by this review.

Barbican already checks the binary data-signature type before maintained
`rpgpie` detached verification. That owner hashes the payload, appends the
signature trailer, validates the digest prefix and invokes public-key
verification; it does not call PGP's newly hardened general data-signature
`Signature::verify` method. No protection is claimed from an uncalled path.
The changed text-normalisation behavior is outside the binary-only route.
Expiry equality, cross-signature validation, exact approved packet equality,
same-primary identity and retained authenticated adverse state remain owned by
the existing adapter/fork and must pass their native controls.

Independent source reviewers found no blocker to bounded native qualification
under this scope. Subsequent actual fixture execution and complete
source/graph/custody reconciliation support the clearance below. Pre-existing
limitations in unused library APIs are recorded privately; those APIs are not
approved by this review.

## Native Qualification and Custody

The full-source candidate is based on published v0.44.0 commit
`ee6e1aa7e89c82bee7e35689d79eb7e40f2c5d92`, using trusted Rust 1.95.0 on
`aarch64-apple-darwin`. Actual locked metadata contains 225 packages; only the
PGP version/checksum changes. Selected features and every other locked package
fact are identical to baseline.

The maintained fork's source code is byte-identical. Its reviewed manifest and
provenance changes are represented by a cumulative patch replayed on the
checksum-authenticated original `rpgpie 0.12.0` archive. All 29 retained upstream
files match; the complete 30-file source receipt has SHA256
`07d1d5f30aa30b3d6fdfdd5e90d7926c556dfcca33947de65eae8dc67debcad2`.
The custody guard passes. A fresh independent reconstruction from the exact
baseline plus the retained patches reproduces every candidate changed file.

Both actual PGP 0.21.0 and 0.21.1 pass all eight focused verifier test groups:
the seven existing groups and one additional armour-boundary qualification.
These cover authentic Rust manifest verification, current subkey selection,
exact expiry boundaries, malformed and unsupported inputs, tampered signatures
and payloads, cross-signatures, authenticated revocation and retained adverse
state. Additional armour cases prove that changed syntactically valid CRC text
preserves decoded packets and the verified signer, trailing ASCII whitespace is
accepted, and trailing non-whitespace, malformed CRC and truncated footer are
refused. CRC checking is disabled on the product path; cryptographic signature
verification authenticates the payload.

The canonical no-flags gate passes, including all-target Clippy with warnings
denied, toolchain conformance, coverage, audit, pins, build and workspace tests:
1,141 passed, zero failed, 19 existing tests ignored. Ignored tests were not
executed. No full upstream PGP suite, new compiler, authentic installation/profile
matrix or additional platform qualification is claimed.

The [qualification receipt](2026-11-19-pgp-0.21.1-qualification.json) binds
the exact candidate, source receipt, reconstruction, commands, results and log
hashes. The [candidate reconstruction patch](2026-11-19-pgp-0.21.1-candidate.patch)
