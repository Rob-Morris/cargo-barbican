## Finding resolved during rehearsal

The original protected v1 run passed the ordinary gate but failed comparative
commands because the scaffold supplied toolchain-only context/storage flags to
`age-lock` and `assess`. The fix removes those flags only from those two calls;
the candidate working directory, exact base and preceding scoped eligibility
check remain intact. The new regression executes generated shell and feeds
its captured arguments through the actual CLI dispatcher.

The immutable v1 controller and its failed runs remain preserved. Reviewed v2
was committed and protected separately; no old controller tag was moved and
no cached-admission fallback was used.

## Limits

This proves these four bounded runs and contemporaneous settings. It is not
new compiler clearance, arbitrary-source safety, a whole-host sandbox proof,
proof of absence of every infrastructure credential, future protection
immutability or an automatic candidate-SHA required check. The four cases do
not exercise GitHub cancellation; existing separate signal/process controls
retain their own limits. Other hosts, evaluator builds, components and
consumers require their applicable qualification and current review.

Barbican's own release workflow, main branch, release tags and normal local
installation were not changed by this rehearsal.
