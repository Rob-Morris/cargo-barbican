# v0.12.1 — 2026-06-26

**Summary** Reject cross-family duplicate advisory bindings

## Fixes

- `reviewed-targets.toml` parsing now rejects the same reviewed advisory (a
  `RUSTSEC-…` id bound to an exact `crate@version`) being declared by more than
  one reviewed family. This affects every command that loads reviewed-targets
  (`pin-check`, `assess`, and the upcoming `audit`).

## Safety

- Closes a cross-family duplicate-binding fail-open: previously two families
  could each bind the same advisory to the same resolved crate, leaving
  ambiguous accountability and a path for a second family to silently extend an
  expired exception with a later `review_by`. A reviewed advisory exception must
  now be owned by exactly one accountable reviewed family.

## Notes

- Adds an internal advisory-evidence library (`barbican::advisory`), not yet
  wired into any command: fail-closed parsers for `cargo-deny -f json` and
  `cargo-audit --json` that enumerate the complete advisory finding set with
  proof of completeness, and a reconciler that classifies findings as accepted,
  expired, or unreviewed against reviewed advisory exceptions. The parsers are
  pinned against real pinned-version scanner-output fixtures. `cargo barbican
  audit` reconciliation that consumes this library lands in a later release.
