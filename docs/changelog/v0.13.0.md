# v0.13.0 — 2026-06-29

**Summary** Add reviewed advisory reconciliation to audit

## Features

- `cargo barbican audit` now reconciles the complete advisory finding set against
  reviewed advisory exceptions instead of inheriting the scanner exit code.
  Barbican generates a max-disclosure cargo-deny runtime config (forced
  `[advisories]`, native advisory ignores and `[graph]` suppression keys
  stripped), runs the configured scanner(s) — `cargo-deny` and/or `cargo-audit` —
  enumerates every advisory finding, reconciles each against bound reviewed
  exceptions, and owns the pass/fail verdict itself.
- Accepted reviewed advisory exceptions render visibly in the `Allowed policy
  exceptions:` register; unreviewed and expired findings fail the audit with a
  per-finding reason.
- Native delegated advisory ignores in `deny.toml` / `.cargo/audit.toml` are
  surfaced under `delegates.unmanaged_delegated_policy` (`warn` | `deny` |
  `allow`); they are neutralised — they cannot hide a finding — and reported.

## Safety

- (I4) cargo-deny native ignores are neutralised by the generated `--config`
  (forced `ignore = []`); `[graph]` suppression keys (`exclude`, `exclude-dev`,
  `exclude-unpublished`, and their root-level aliases) are stripped while
  relevance scope (`targets`, feature flags) is preserved. cargo-audit
  `.cargo/audit.toml` ignores are neutralised by running from a controlled
  working directory, and a non-empty runtime `settings.ignore` fails the audit.
- (I5) the verdict is computed from reconciliation plus parsed scanner signals,
  not the scanner exit code: a non-zero scanner exit is normal when findings
  exist, and an unexplained non-zero with no parseable summary fails closed.
- (I2/I3) structured scanner output parses fail-closed — a missing terminal
  cargo-deny summary, a configured check absent from the summary, or counted
  advisory errors with nothing enumerated all fail the audit rather than
  reporting clean.
- cargo-audit fetches a fresh advisory database each run (matching cargo-deny),
  so a stale local database cannot silently miss a newly published advisory; a
  failed fetch fails the audit closed.
- Optional policy files (`deny.toml`, `.cargo/audit.toml`) are refused when they
  are symlinks, so a symlinked policy file cannot leak an unrelated file's
  contents through a parse-error diagnostic.

## Notes

- Advisory exceptions are honoured only through the bound surface (resolved-target
  and checksum match, review-record existence, and `review_by` expiry via the
  shared UTC clock); the raw unbound accessors are never consulted for
  suppression.
- Templates, the `policy init` scaffold, inventory advisory reporting, and the
  remaining user-facing docs for this workflow land in a later release.
