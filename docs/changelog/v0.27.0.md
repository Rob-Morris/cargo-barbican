# v0.27.0 — 2026-08-03

**Summary** Let native advisory ignores coexist with governed exceptions

## Features

- Lets native cargo-deny and cargo-audit advisory ignores coexist with
  Barbican's governed exceptions. Native ignores remain neutralised during
  Barbican's maximum-disclosure scan and never authorise a pass; an ID is
  reported as governed only when every current occurrence is accepted by an
  active checksum-bound, reviewed, expiring exception. Unmatched IDs retain
  the configured unmanaged-ignore posture, and the shipped `deny.toml` now
  includes a normal advisory table for direct cargo-deny use.

## Contract

- Bumps `audit --format json` to `schema_version` 5. Each native delegated
  ignore entry now separates `governed_advisory_ids` from
  `unmanaged_advisory_ids` while retaining the original `advisory_ids` and
  reporting policy.
- Preserves Barbican's maximum-disclosure security invariant: for an unchanged
  dependency graph and Barbican policy, adding an advisory ID to a native
  ignore list cannot change the Barbican verdict from failure to success.

## Distribution

- Documents that installing from the immutable git tag needs
  `net.git-fetch-with-cli` while the repository is private: cargo's built-in
  git fetcher cannot invoke a shell-command `credential.helper` such as the one
  `gh auth login` installs, so the documented install command failed with
  `failed to authenticate when downloading repository` even for a maintainer
  whose `git` CLI could clone the repo. README, `docs/user/integration.md`, and
  `docs/user/ci.md` now carry the requirement, including what a consumer CI job
  additionally needs (a token that can read the private source). The
  requirement lapses when the repository becomes public and the clone is
  anonymous.
