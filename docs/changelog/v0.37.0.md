# v0.37.0 — 2026-11-04

**Summary** Review and admit Rust toolchains before execution

- Add direct trusted `toolchain review` and explicit `accept`, with original
  signed official inputs, bounded archive mapping and scoped source/security
  evidence. Personal acceptance remains separate from portable repository
  assessment and current policy admission.
- Add checked `install`, static `adopt` / `installation-check`,
  `admission-check` and separate guarded `activate`. Native operations admit
  only the qualified macOS ARM64 Rustup build and minimal host scope with
  supported Clippy/rustfmt additions; default/docs, cross-targets and other
  evaluator/host combinations explicitly refuse.
- Add per-user public trust `show` / `refresh` / `approve` with material-change
  proposals, retained adverse observations and separate private authority and
  disposable cache. Explicit cached admission is bounded per operation;
  unchanged continuing use retains current policy and installed-byte checks.
- Opt existing gates into static pre-Cargo admission through
  `[toolchain].require_admission` and explicit governance scope. Preserve
  legacy conformance meanings and crate-family coverage requirements.
- Govern the maintained embedded verifier, bounded distribution decoders and
  scoped cancellation dependencies. Preserve exact source custody, visible
  public-verification advisory exceptions and strict sibling pin identities.
- Document trusted bootstrap, portable CI acceptance, source uncertainty,
  initial-default ownership, cancellation, retained failures and unsupported
  native scope in the toolchain guide and functional contract.
