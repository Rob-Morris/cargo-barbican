# v0.6.0 — 2026-06-07

**Summary** Add elevated-risk policy workflow and gatehouse dossiers

## Features

- Adds `assess --policy-mode elevated-risk` for explicit invocation-scoped
  acceptance of elevated-risk findings while policy-violating findings still
  fail.
- Adds reviewed execution-surface allowances for exact `build-rs`,
  `proc-macro`, and `native-sys` crate selections, with visible audit-trail
  output and fail-closed review-record checks.
- Adds `cargo barbican gatehouse candidate` to assemble isolated exact
  candidate intake dossiers without compiling or running candidate code.

## Hardening

- Broadens inspection and assessment coverage for malformed manifests, path
  and workspace dependencies, native linking metadata, yanked crates.io
  responses, and same-version Cargo.lock checksum drift.
- Hardens dry-run workspace copying with private scratch directories and safe
  relative symlink preservation only when the resolved target stays inside the
  workspace and outside skipped `.git` / `target` paths.
- Validates crates.io base URLs, exact crate names and versions, SHA-256
  digests, review-record paths, workspace members, and reviewed-target inputs
  at their trust boundaries.
- Makes `verify` fail closed when `reviewed-targets.toml` is absent or not a
  regular file, while standalone `pin-check` remains a lenient diagnostic.
- Updates consumer integration and template sync guidance to the `v0.6.0`
  reviewed-target workflow.
