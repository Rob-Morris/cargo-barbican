# v0.13.1 — 2026-06-29

**Summary** Harden policy-file reads against symlink disclosure

## Safety

- `barbican.toml` and `reviewed-targets.toml` are now read through the
  symlink-rejecting reader: if either is a symlink, the command fails closed
  instead of following the link. This closes a disclosure vector where an
  untrusted checkout could symlink a barbican-specific policy file (not used by
  cargo, so the build still works) to a secret the build user can read — e.g.
  `.env`, `~/.netrc`, `~/.ssh/...` — and have a fragment leaked through the TOML
  parse-error diagnostic on stderr / CI logs. `deny.toml` and
  `.cargo/audit.toml` already gained this protection in v0.13.0.
- Absent files still fall back to the default config / no reviewed targets, and
  regular policy files load unchanged.

## Notes

- `Cargo.toml` / `Cargo.lock` reads are intentionally unchanged: a symlinked
  manifest or lockfile would also break cargo itself, so it is not a realistic
  vector. Suppressing the embedded source snippet from parse-error diagnostics
  for all untrusted inputs remains a tracked, deeper-layer hardening.
