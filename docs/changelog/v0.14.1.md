# v0.14.1 — 2026-07-01

**Summary** Harden checksum-set matching and terminal-output hygiene

## Safety

- Reviewed-target resolved checks now require the observed checksum set to be
  exactly the expected singleton, mirroring the existing version singleton
  check. A degenerate `Cargo.lock` carrying an extra checksum line for one
  name+version can no longer satisfy a checksum-bound reviewed target.
- The reviewed-targets parser and both CLI render escapers now reject or escape
  the full bidi and zero-width/invisible Trojan-source class: bidi
  embeddings/overrides/isolates, bidi marks LRM/RLM/ALM, ZWSP/ZWNJ/ZWJ/WJ,
  BOM, and interlinear-annotation codepoints. The `resolve --dry-run`
  `Cargo.lock` diff is routed through the diagnostic escaper so
  attacker-controlled `Cargo.lock` source fields cannot inject terminal
  reordering while diff line structure is preserved.

## Notes

- Internal: boxed the oversized `CommandError` parse variant and dropped the
  clippy `large-error-threshold` override. This has no CLI behaviour change.
