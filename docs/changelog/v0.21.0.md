# v0.21.0 — 2026-07-09

**Summary** Add advisory remediation guidance to audit findings

## Features

- `cargo barbican audit` now prints a read-only remediation hint for each
  failing (unreviewed or expired) advisory finding that has a published patched
  release. It classifies the fix as a direct pinned-manifest edit, a direct
  `cargo barbican update`, or a transitive parent bump, and — for transitive
  findings — names the nearest parent from the dependency path while warning
  that the vulnerable crate often cannot be bumped on its own.
- The `--format json` report carries a per-finding `remediation` object (or
  `null`) with the kind, patched ranges, target crate, nearest parent, and a
  command hint. Its `schema_version` advances to `2`.

## Contract

- The JSON schema evolution rule changed in this release, not merely gained a
  record: the v0.20.0 contract treated adding optional fields as a
  schema-version-compatible change, while from schema version `2` adding,
  removing, or renaming fields also requires a new `schema_version`.
  (This note was added retrospectively in v0.21.1 after a contract review
  found the rule change was shipped without being recorded.)

## Safety

- Remediation guidance is deliberately conservative: it never suggests moving an
  exact `=` pin with a lockfile-only update, never fabricates an exact target
  version offline, and always points to `--dry-run` verification, so the gate
  cannot emit a remediation that would silently fail or mislead a reviewer.
