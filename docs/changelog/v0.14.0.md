# v0.14.0 — 2026-06-30

**Summary** Add inventory advisory reporting and deny.toml scaffold

## Features

- `cargo barbican inventory` now reports reviewed advisory exceptions and
  advisory delegation state. Exceptions are shown with their binding and expiry
  status, including active, soon-to-expire, expired, and stale states.
- `cargo barbican inventory` now renders the configured advisory scanner,
  `cargo-deny` check groups, unmanaged delegated-ignore policy, native advisory
  ignores, and whether `cargo-deny` non-advisory posture comes from a checked-in
  `deny.toml` or Barbican's generated default base.
- `cargo barbican policy init` now scaffolds `deny.toml` when it is absent.
- The shipped `barbican.toml` template now carries explicit `[delegates]`
  defaults, and the `reviewed-targets.toml` template includes a commented
  `allowed_advisories` example.

## Safety

- The shipped `deny.toml` template carries non-advisory `cargo-deny` posture
  only. It deliberately omits `[advisories]`, because `cargo barbican audit`
  forces advisory disclosure in its runtime cargo-deny config.
- `policy init` uses create-if-missing semantics for `deny.toml`: it never
  overwrites or weakens an existing regular file.

## Notes

- The user-facing docs now cover the v0.13.0 audit reconciliation workflow:
  Barbican owns the advisory verdict instead of inheriting scanner exit codes,
  and native advisory ignores are neutralised before being reported.
