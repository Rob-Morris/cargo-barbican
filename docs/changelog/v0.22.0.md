# v0.22.0 — 2026-07-14

**Summary** Add pin exception for governed advisory acceptance

## Features

- `cargo barbican pin exception <crate>[@version] <advisory-id>... [--review-by
  YYYY-MM-DD]` scaffolds the governed acceptance of one or more RustSec
  advisories, fully offline: a `reviewed-targets.toml` family stub carrying
  checksum-bound `allowed_advisories` entries with a re-review deadline
  (default 30 days), plus a review-record markdown stub pre-filled with the
  accepted advisories. This closes the mis-incentive where the ungoverned
  `deny.toml` ignore was one line while the governed reviewed exception was
  unassisted.
- `cargo barbican audit` now renders a `governed exception:` pointer to the
  scaffolder on each unreviewed RustSec finding, after the remediation hint so
  the acceptance path never outranks the fix.

## Safety

- The scaffolder is fail-closed and refuses to rewrite existing policy: a
  crate already covered by a reviewed family gets the exact
  `allowed_advisories` fragment to paste plus the record to update, never a
  mechanical rewrite of the family block. Checksumless lockfile entries,
  already-allowed advisories, resolved-version drift, version-only covered
  entries, id/date parse failures, and name or record collisions all exit 1
  without mutating anything, and the appended policy text is re-parsed before
  it is written.
- The scaffold is not a completed review: the record stub must be completed by
  a human reviewer, and `audit` fails the exception once `review_by` passes.
