# v0.41.1 — 2026-11-13

**Summary** Keep distinct provisional RustSec findings before admission

- Collect supported unassigned RustSec records without treating the shared
  placeholder as a unique advisory. Bind each provisional issue to its exact
  source path and bytes, preserving assigned advisory identities.
- Keep every distinct affected source finding in the toolchain review and
  assessment set. Consolidate only identical repeated findings and refuse
  conflicting identities; provisional status adds no admission exemption.
- Show finding context in newly generated toolchain review templates and name
  the source path when parsing unsupported advisory input fails. Material
  fresh evidence changes still require exact reassessment through the existing
  review, acceptance and eligibility owners.
- Retain existing evidence schemas and historical cached/continuing-use
  boundaries. No automatic assignment discovery, inherited approval, new CLI
  flag or weakening of known applicable adverse-finding refusal is introduced.
