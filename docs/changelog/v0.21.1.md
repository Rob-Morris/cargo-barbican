# v0.21.1 — 2026-07-14

**Summary** Harden audit remediation classification and output contracts

## Fixes

- A manifest requirement now classifies an advisory finding as direct only
  when it can admit the finding's resolved version. Previously classification
  matched by crate name alone, so a vulnerable transitive duplicate (for
  example a capped `hashbrown 0.12` beside a safe direct `hashbrown = "0.15"`)
  received direct-update advice aimed at the already-safe copy.
- Remediation collection is now best-effort like dependency-path collection:
  a workspace manifest that barbican cannot read or parse omits the hints and
  writes a `note: remediation context unavailable` diagnostic to stderr
  instead of suppressing the entire report (including the `--format json`
  body) exactly when failing findings exist.
- The direct-update remediation wording now lists all patched-version ranges
  rather than only the range embedded in the `pick` hint.

## Contract

- The schema version `2` stable field list now records the emitted per-finding
  `cvss` and `informational` fields, enumerates the `status` and `disposition`
  value sets, and defines the kind-dependent meaning of
  `remediation.target_crate`.
- The v0.21.0 changelog entry now records that the JSON schema evolution rule
  changed in that release (additive fields stopped being
  schema-version-compatible); the rule change had shipped unrecorded.
- The stream-discipline contract now covers non-failure `note:` diagnostics on
  stderr for degraded report enrichment, and the dependency-path wording no
  longer claims workspace-root origin (the path starts from the nearest
  workspace member).

## Tests

- The stable JSON contract fields (`completeness_failures`, `cargo_deny`,
  `cargo_audit`, `native_delegated_ignores`), the BFS shortest-path property
  (diamond graphs, multi-member workspaces, cyclic resolve graphs),
  remediation on expired dispositions, the `direct-pinned-edit` and
  `direct-update` JSON kinds, terminal escaping of untrusted advisory titles
  and patched ranges, the workspace-inherited exact-pin loader wiring, and
  cvss extraction with its risk-label fallback are now all pinned by tests.
