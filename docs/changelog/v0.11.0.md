# v0.11.0 — 2026-06-22

**Summary** Add reviewed advisory exception config and parsing

## Features

- Adds the `[delegates]` section to `barbican.toml`: advisory scanner selection
  (`delegates.advisories.lockfile_scanner` = `cargo-deny` | `cargo-audit` |
  `both`), configurable cargo-deny check groups (`delegates.cargo_deny.checks`),
  and `delegates.unmanaged_delegated_policy` (`warn` | `deny` | `allow`), with
  defaults and cross-field validation.
- Adds `allowed_advisories` to reviewed Rust families in `reviewed-targets.toml`:
  structured `{ id, review_by }` entries bound to an exact, checksum-bound
  resolved crate and the family review record, parsed into a typed
  `RustSecAdvisoryId` and ISO `review_by` date.
- Parses fail-closed: malformed RustSec IDs, missing or unparsable `review_by`,
  empty lists, duplicate advisory IDs within a crate, crates absent from the
  family `resolved` map, and checksum-less crates.io targets are all rejected.

## Safety

- Hardens reviewed-targets string fields against terminal control-character
  injection: `family` and `review_record` reject blank and control characters
  (C0/DEL/C1 plus U+2028/U+2029) at parse; `ReviewedTargetsError`,
  `ExactCrateSpecError`, and `ExactVersionRequirementError` debug-escape
  TOML-sourced strings; and the CLI render sink escapes control characters in
  parse-error diagnostics while preserving newlines for readability.

## Notes

- Reviewed advisory exceptions are parsed and validated only; `audit` does not
  yet consume them. Scanner reconciliation enforcement lands in a later cluster.
