# v0.7.0 — 2026-06-09

**Summary** Add policy init adoption scaffold

## Features

- Adds `cargo barbican policy init`, a deterministic command that scaffolds a
  consumer repo's explicit adoption surface — `barbican.toml`,
  `reviewed-targets.toml`, `docs/dependency-reviews/`, and its `README.md` —
  from embedded templates, without reviewing or certifying existing
  dependencies.
- Creates each scaffold item independently in dependency order and reports a
  per-item status table, so repairable pieces are still laid down when another
  item is blocked.
- Ships `templates/barbican.toml` and consumer adoption docs
  (`docs/user/adoption.md`, `docs/user/commands.md`) covering onboarding and
  the re-sync workflow.

## Hardening

- Fails closed on wrong-type, symlink, and blocked-ancestor scaffold paths
  using no-follow `symlink_metadata`, with containment enforced inside the
  scaffold state machine (`confined_scaffold_state` / `ScaffoldState`) rather
  than by caller convention.

## Documentation

- Adds a `Platform Support` posture (Unix-first; Windows experimental and
  unverified) and non-sequenced design stubs to
  `docs/architecture/overview.md`: Full Windows Support, Race-Free Filesystem
  Containment, and Reviewed-Target Source-Kind Enforcement.

## Repo

- Adopts a dogfooded verification gate (`scripts/verify.sh`,
  `scripts/check_doc_versions.sh`), exact direct-dependency pins, and a
  self-adoption `reviewed-targets.toml`, so cargo-barbican enforces its own
  supply-chain policy before shipping this version.
