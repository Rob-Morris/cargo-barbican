# v0.8.0 — 2026-06-14

**Summary** Add reviewed release-age exceptions

## Features

- Adds `allowed_age_exceptions` to reviewed Rust families in
  `reviewed-targets.toml`, allowing an intentionally accepted too-fresh exact
  `crate@version` to pass release-age gates when it is already present in the
  same family `resolved` map with `checksum_sha256`.
- Threads reviewed release-age exceptions through `age`, `age-lock`, `resolve`,
  `assess`, `inspect`, and `gatehouse candidate`, with yanked releases,
  checksum mismatches, fetch failures, and inspection findings remaining
  blocking.
- Renders applied release-age exceptions under visible allowed-policy output
  and reports checksum mismatches as blocking policy findings.

## Safety

- Validates release-age exception entries fail closed when the target is absent
  from the same family `resolved` map, lacks `checksum_sha256`, or declares a
  version that differs from the resolved version.
- Requires the family `review_record` to exist before an exception can be
  honoured; missing records fail loudly only when the exception would be needed
  to waive a too-fresh release.
- Compares reviewed checksums uniformly at the shared release-age seam. Metadata
  commands compare against crates.io's published checksum metadata; inspect
  paths additionally verify downloaded tarball bytes.

## Documentation

- Updates `templates/reviewed-targets.toml`,
  `templates/dependency-reviews/README.md`, `docs/functional/cli.md`,
  `docs/user/commands.md`, and contributor specification docs to describe the
  release-age exception contract and review-record trust model.
