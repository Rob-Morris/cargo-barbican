# v0.26.0 — 2026-08-03

**Summary** Stream verify's build and test delegate output live

## Features

- Streams the `cargo build --locked` and `cargo test --locked` delegate
  output in `verify` (and therefore `gatehouse pre-release`) live instead of
  capturing it silently and embedding it in the failure message. Delegate
  stdout is inherited directly, while stderr is relayed with a
  `delegate stderr: ` prefix that reserves line-leading `FAIL ` for
  cargo-barbican's terminal failure signal. Delegate stdin is closed so a
  build or test cannot block on or consume operator input. A long test run no
  longer looks like a hang, and compiler and test-harness detail appears at
  the moment it is produced. Delegates whose output barbican parses
  (cargo-deny, cargo metadata, and the other evidence sources) keep captured
  execution unchanged.

## Contract

- The failure line for a failed build/test step is now
  `FAIL cargo <step> --locked: command exited with status N` on stderr,
  without the previously embedded `stdout:`/`stderr:` blobs — the delegate's
  output has already reached the terminal above it. The failure detail text
  was never a stable parse target; stable tokens remain authoritative only
  together with the command's exit code, the stderr failure contract is the
  line-leading `^FAIL ` token, and all exit codes are unchanged.
- `verify` flushes its buffered report lines before each delegate handoff so
  the `Pin check:` report and `OK   cargo build --locked` confirmation
  cannot land after the delegate output that follows them when stdout is
  block-buffered (for example under a CI pipe).
