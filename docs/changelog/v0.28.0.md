# v0.28.0 — 2026-08-06

**Summary** Pin Rust toolchains before execution gates

## Features

- Requires `verify` and `gatehouse pre-release` to establish an exact native
  `rust-toolchain.toml` policy before dependency-policy, build, or test work.
  Full stable releases, numbered beta prereleases, and dated nightlies are
  accepted; bare versioned betas, floating channels, path toolchains, legacy `rust-toolchain`
  shadowing, symlinked policy, and unverifiable tool state fail closed.
- Proves the active rustup toolchain and the Cargo, rustc, and rustdoc
  release/host facts agree with the pin. `RUSTC`, `CARGO_BUILD_RUSTC`, `RUSTC_WRAPPER`,
  `CARGO_BUILD_RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER`,
  `CARGO_BUILD_RUSTC_WORKSPACE_WRAPPER`, `RUSTDOC`, `CARGO_BUILD_RUSTDOC`,
  effective hierarchical Cargo
  `[build].rustc`, `[build].rustc-wrapper`,
  `[build].rustc-workspace-wrapper`, `[build].rustdoc`, and indirect
  Cargo-config includes block the gate because they make the Rust toolchain
  executable inputs ambiguous. If neither
  `CARGO_HOME` nor `HOME` establishes the user-level Cargo config location,
  the gate fails closed instead of silently skipping that policy input.
- Loads source-replacement policy across the same effective Cargo config
  hierarchy: workspace root, ancestors, and Cargo home. Repo-side config
  symlinks remain refused; a Cargo-home config symlink is inspected only when
  Cargo home and its target both resolve outside the workspace and the target
  is a readable regular file. Repo-local Cargo homes retain the repository
  refusal.
- Defines the boundary explicitly: this is a Rust toolchain-executable identity
  gate, not binary-provenance attestation or a sandbox for Cargo's wider
  runner/linker/flags/environment execution surface. `RUSTUP_HOME` therefore
  remains an allowed rustup installation-location control.
- Extends `policy init` with `--toolchain <exact-channel>`. An absent native
  pin is created only from that explicit operator choice; a conflicting pin is
  preserved and reported, and `--ci github` is not emitted without valid
  toolchain policy. Created toolchain policy uses rustup's `minimal` profile,
  and the init report makes that choice visible.

## Contract

- Adds stable `Toolchain check: PASS` / `Toolchain check: FAIL` report tokens
  and `Gatehouse pre-release: FAIL (toolchain)`. Gatehouse now has four
  fail-fast steps and performs the toolchain preflight once before inventory,
  audit, and verify. Nested verify now requires the completed preflight
  evidence instead of relying on a naming convention.
- Adds `rust-toolchain.toml` to the `review` command's policy-relevant root
  paths and to the documented CODEOWNERS surface.
