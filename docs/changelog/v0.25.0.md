# v0.25.0 — 2026-08-03

**Summary** Enforce declared deny.toml licence policies by default

## Features

- Makes the default `delegates.cargo_deny.checks` set presence-driven: when
  the key is unset in `barbican.toml`, `cargo barbican audit` runs the
  cargo-deny `advisories`, `bans`, and `sources` checks and adds the
  `licenses` check whenever the checked-in `deny.toml` declares a
  `[licenses]` policy. A checked-in licence policy is treated as expressed
  intent to enforce it — previously `audit` silently never ran the licenses
  check unless `checks` opted in explicitly.
- Keeps an explicit `delegates.cargo_deny.checks` list authoritative in both
  directions: include `"licenses"` to force the check regardless of
  `deny.toml` content, or omit it to skip the check even when a `[licenses]`
  policy is checked in.
- Renders the resulting licences posture in every `audit` report
  (`cargo-deny licenses check: enforced | skipped | disabled`, with the
  reason) and in the `inventory` advisory-delegation section alongside the
  resolved check set and its source, so the effective state is never
  invisible.
- Bumps the `audit --format json` contract to `schema_version` 4, adding
  `cargo_deny.licenses` with `posture` (`enforced` | `skipped` | `disabled`)
  and `reason` (`deny-toml-policy` | `explicit-checks` |
  `no-deny-toml-policy`), documented in `docs/functional/cli.md`.
- Updates the `policy init` scaffold templates: `templates/barbican.toml`
  now documents the presence-driven default with `checks` commented out, and
  `templates/deny.toml` carries a commented `[licenses]` example explaining
  the opt-in.

## Hardening

- Declares a `[licenses]` policy in this repo's own `deny.toml`, so
  cargo-barbican enforces licence checking on its own dependency graph instead
  of shipping a gate it does not run. The allow list is minimal — `MIT`,
  `Apache-2.0`, `ISC`, `Unicode-3.0`, `BSD-3-Clause`, `CDLA-Permissive-2.0` —
  and every entry is required by a resolved crate, with the reasoning recorded
  in `docs/dependency-reviews/2026-08-03-licence-policy.md`.
- Fixes the generated `policy init --ci github` workflow, which failed on any
  runner with a cold Cargo cache: the gate resolves frozen cross-platform
  `cargo metadata`, so crates a host build never downloads (Windows-only ones
  such as `anstyle-wincon`) were missing and enforcement could not establish
  coverage. The workflow now runs `cargo fetch --locked` with no `--target`
  before the gate.

## Distribution

- README carries an explicit early-adopter and use-at-your-own-risk callout at
  the top, alongside Security, Contributing, and Licence sections and a CI
  status badge, so the release's maturity and reporting channels are visible
  from the front door.

## Notes

- Library surface: `CargoDenyDelegatesConfig.checks` is now
  `Option<Vec<CargoDenyCheck>>` with `resolved_checks` /
  `licenses_posture` resolution helpers, plus the new
  `CargoDenyLicensesPosture` type and
  `deny_toml_declares_licenses_policy` parser in `crates/barbican`.
- With the check enabled and no checked-in `[licenses]` table (explicit
  opt-in only), the generated runtime config still carries an empty licences
  policy that rejects every licence — unchanged fail-closed behaviour.
