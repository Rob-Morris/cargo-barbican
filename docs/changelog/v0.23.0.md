# v0.23.0 — 2026-07-14

**Summary** Name provable advisory blockers from requirement edges

## Features

- `cargo barbican audit` now parses the declared requirement edges from cargo
  metadata (`packages[].dependencies[].req`) — the semver requirements each
  resolved parent states — across all resolved parents of a vulnerable crate,
  not only the shortest-path parent.
- Transitive remediation hints are upgraded from a hedge to a proof where one
  exists: a provably capped finding names each blocking parent and its
  requirement ("capped by plist@1.9.0 (requires ^0.39)") and directs the fix
  at the blocker — a manifest edit when the blocker is exact-pinned, a
  targeted `update` otherwise; a provably uncapped finding reports that the
  vulnerable crate itself can move with a lockfile-only
  `cargo barbican update` (new remediation kind `transitive-update`).
- Direct/transitive classification is now metadata-first: a workspace-member
  resolve edge onto the exact vulnerable package decides the direct case,
  which is version-precise and immune to the manifest rename and
  duplicate-version blindness of name-based matching. Manifest-based
  classification remains as the fallback when metadata is unavailable.
- The `--format json` report advances to `schema_version` 3: the remediation
  object gains `blockers` (`null` when the analysis was unavailable or
  indeterminate, `[]` when provably uncapped, else
  `{crate, version, requirement}` entries), findings gain a
  `governed_exception` command hint for the `pin exception` scaffolder, and
  the top level gains `remediations_available`. The contract now also
  enumerates the `status` and `disposition` value sets and defines
  `target_crate` semantics per kind.

## Safety

- Blocker and uncapped claims come only from decidable semver-interval
  proofs: every Cargo requirement op is an interval, a comma requirement is
  an intersection, and a patched list is a union, so overlap is computed
  exactly. Pre-release comparators, unparseable requirements, and resolve
  edges without a matching declaration make the analysis indeterminate and
  fall back to the shipped conservative hedge — the gate still never tells a
  user to bump a crate a parent provably caps.
