# Integration

How a consumer repo adopts cargo-barbican.

> This document describes the planned flow. The implementation that makes
> these steps work does not yet exist end-to-end.

## Planned consumer flow

1. Install:

   ```bash
   cargo install --locked --git https://github.com/rob-morris/cargo-barbican --tag v0.1.0
   ```

2. Copy templates into the consumer repo:

   ```bash
   # From the cargo-barbican repo root:
   cp templates/deny.toml /path/to/consumer/
   cp templates/dependency-management.md /path/to/consumer/docs/contributor/
   cp -r templates/dependency-reviews /path/to/consumer/docs/
   ```

3. Write the first inherited review records:
   - `cargo-barbican` itself, as the tool install
   - `cargo-audit` and `cargo-deny`, as prerequisite tooling

4. Run the smoke checks:

   ```bash
   cargo barbican audit
   cargo barbican verify
   ```

5. Update the consumer repo's `AGENTS.md` so dependency-gate instructions
   point at `cargo barbican` instead of a manual process.

## Versioning and re-sync

Consumers pin a specific tag. Template files should include a header comment:

```text
# Synced from cargo-barbican v0.1.0
# Edit upstream and re-sync; do not edit this file directly.
```

When cargo-barbican releases a new version, the consumer:

1. Re-runs the copy step from the new tag.
2. Reviews the diff.
3. Updates the tool-install review record to cite the new version.

There is no automatic sync mechanism in v0.1. Re-sync is deliberate and
reviewed.
